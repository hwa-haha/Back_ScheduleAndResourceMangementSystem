**작성자**: Kyuhyun Kim

**메시지**:  
`feat: add slotIntervalMinutes parameter for time slot queries - updated resource management APIs and DTOs to include optional slot interval configuration, enhancing flexibility in time slot availability requests.`

### 요약

- **리소스 관리(시간 슬롯)**: 시간 슬롯 조회 시 **슬롯 간격(분)** 을 쿼리 파라미터로 받을 수 있도록 `slotIntervalMinutes` 추가.
- 기존에는 30분 고정이었으나, **선택 파라미터로 간격을 지정**할 수 있어 유연성이 높아짐.
- 디버깅용 `console.log` 제거.

### 변경 파일 (4개)

| 파일 | 변경 내용 |
|------|-----------|
| `dist/main.js` | 빌드 결과물 반영 (API 문서·DTO·서비스 로직) |
| `src/business/resource-management/controllers/resource/resource.controller.ts` | API 문서(주석) 수정 |
| `src/business/resource-management/dtos/resource/resource-query.dto.ts` | DTO에 `slotIntervalMinutes` 추가 |
| `src/business/resource-management/services/resource.service.ts` | 쿼리 사용처·슬롯 계산 로직에 `slotIntervalMinutes` 반영, console 제거 |

### 상세 변경 내용

#### 1. ResourceQueryDto (`resource-query.dto.ts`)

- **추가 필드**: `slotIntervalMinutes?: number`
  - 설명: 슬롯 간격(분). 시간 슬롯 생성 시 간격 설정. 기본값 30.
  - `@ApiPropertyOptional`, `@IsOptional()`, `@IsNumber()`, `@Min(1)`, `@Type(() => Number)` 적용.

#### 2. ResourceController (`resource.controller.ts`)

- API 설명 주석 수정:
  - "30분 단위" → "시간 슬롯 단위"
  - 선택 파라미터에 `slotIntervalMinutes (슬롯 간격, 기본값: 30분)` 명시
  - 예시 쿼리에 `slotIntervalMinutes=30` 추가

#### 3. ResourceService (`resource.service.ts`)

- **findAvailableTime**
  - `query`에서 `slotIntervalMinutes` 추출 후, 시간 슬롯 계산 시 전달.
  - `console.log` 4곳 제거 (조회 시작/오늘 날짜, dateRange, resource, reservations).

- **calculateTimeSlotAvailability**
  - 인자에 `slotIntervalMinutes: number = 30` 추가.
  - `calculateAvailableTimeSlots` 호출 시 `slotIntervalMinutes` 전달.
  - `console.log('timeRange', ...)` 제거.

- **calculateAvailableTimeSlots**
  - 인자에 `slotIntervalMinutes: number = 30` 추가.
  - 기존 내부 상수 `const slotIntervalMinutes = 30` 제거 → 인자 사용.
  - 주석: "30분 단위" → "시간 슬롯별".
  - `console.log('startDateTime', ...)` 제거.

### API 사용 예

- 기존: `?resourceType=MEETING_ROOM&resourceGroupId=xxx&startDate=2024-01-15&endDate=2024-01-15&timeUnit=30&pm=true`
- 변경 후: `?...&timeUnit=30&slotIntervalMinutes=30&pm=true` (생략 시 30분 유지)

## 커밋 2: `3d17e862e5be49a8b0711433957b7f2243c531ce`

**작성자**: Kyuhyun Kim  
**날짜**: 2026-01-26 10:58:25 +0900  

**메시지**:  
`feat: add optional linkUrl parameter to notification services and DTOs - enhanced notification functionality by allowing an optional link URL for notifications, improving user engagement and interactivity.`

### 요약

- **알림 기능**: 알림 전송 시 **선택적으로 링크 URL(`linkUrl`)** 을 지정할 수 있도록 전 구간에 파라미터 추가.
- 컨트롤러 → 비즈니스 서비스 → 컨텍스트 서비스 → FCM 어댑터·페이로드까지 `linkUrl` 전달.
- 기본 링크를 `/plan/user/schedule-add`에서 `/current/sms/schedule-status`로 변경.
- FCM 기본 URL 변경 및 metadata에 `linkUrl` 포함.

### 변경 파일 (5개)

| 파일 | 변경 내용 |
|------|-----------|
| `src/business/notification-management/controllers/notification.controller.ts` | 컨트롤러에서 `linkUrl` 전달 |
| `src/business/notification-management/notification-management.service.ts` | 서비스 시그니처·호출에 `linkUrl` 추가 |
| `src/context/notification/adapter/fcm.adapter.ts` | FCM URL 변경, payload metadata에 `linkUrl` 추가 |
| `src/context/notification/dtos/create-notification.dto.ts` | SendNotificationDto에 `linkUrl` 필드 추가 |
| `src/context/notification/services/notification.context.service.ts` | 알림 전송 프로세스에 `linkUrl` 인자·기본값 반영 |

### 상세 변경 내용

#### 1. SendNotificationDto (`create-notification.dto.ts`)

- **추가 필드**: `linkUrl?: string`
  - `@ApiPropertyOptional({ description: '알림 링크 URL' })`
  - `@IsOptional()`, `@IsString()`

#### 2. NotificationController (`notification.controller.ts`)

- 알림 전송 호출 시 `sendNotificationDto.linkUrl` 인자로 추가 전달.

#### 3. NotificationManagementService (`notification-management.service.ts`)

- `sendNotification(...)` 메서드에 **선택 인자** `linkUrl?: string` 추가.
- 컨텍스트 서비스 호출 시 `linkUrl` 전달.

#### 4. NotificationContextService (`notification.context.service.ts`)

- `알림_전송_프로세스를_진행한다(..., linkUrl?: string)` 에 `linkUrl` 추가.
- 포털 알림 payload의 `linkUrl`:
  - 기존: `'/plan/user/schedule-add'` (하드코딩)
  - 변경: `linkUrl || '/current/sms/schedule-status'` (인자 우선, 없으면 기본값).

#### 5. FCMMicroserviceAdapter (`fcm.adapter.ts`)

- **기본 FCM API URL** 변경:
  - 이전: `https://lumir-notification-server-git-fcm-lumir-tech7s-projects.vercel.app`
  - 이후: `https://lnms-dev.lumir.space`
- **metadata** 에 `linkUrl: payload.linkUrl` 추가 (payload에 있으면 그대로 전달).

### 동작 정리

- 관리자/API에서 알림 전송 시 `linkUrl`을 넣으면 해당 URL이 포털 알림 링크로 사용됨.
- `linkUrl`을 보내지 않으면 기본 `/current/sms/schedule-status` 사용.
